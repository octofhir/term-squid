# Native LOINC primary-table provider and typed lookup

November 3, 2026. This increment follows [implicit SNOMED membership](IMPLICIT_MEMBERSHIP_REPORT.md). It implements a missing ingestion/provider foundation while full clinical archives are unavailable. Generated fixtures and measurements are diagnostic, not a substitute for the pinned HealthSamurai corpus.

## Import and activation

`term-squid-cli import-loinc --manifest FILE [--dry-run]` streams a locally supplied UTF-8 `Loinc.csv`, including BOM, quoted commas/newlines and Unicode. It verifies a lowercase SHA-256 of the original byte stream and an operator-attested exact row count. No download, archive extraction or release-sized Rust map is involved. The new `csv = 1.4.0` dependency is locked; an additional bounded streaming syntax guard rejects malformed quotes that the decoder deliberately accepts.

The manifest must identify format `loinc-csv-v1`, a numeric business version, `completeTable=true`, source path/hash and positive `expectedConcepts`. Paths are relative to the manifest. The [template](../benchmarks/loinc-csv.template.json) intentionally fails unchanged. The loader cannot prove that an operator-supplied file is an authentic complete release merely from its hash/count; acquisition and completeness remain explicit provenance responsibilities. `VersionLastChanged` is not substituted for the release version.

COPY writes a transaction-local staging table. Hash, syntax, row count and identifier uniqueness are checked before publication. Metadata, all raw source fields, concept projections and provenance activate in one transaction. A per-version database advisory lock plus a fresh conflict check serializes concurrent activation. Re-import of the identical version/fingerprint is unchanged and does not refresh its activation timestamp; changed content/context under an existing version fails. Dry runs, malformed data, publication errors and cancellation leave no partial release. The fingerprint includes source SHA/count, business version and projection revision, not the local path.

Migration `20261103000003_loinc_csv` adds `loinc_releases` and `loinc_terms`, extends the native-provider constraint and tracks their writes through the existing generation triggers. Apply all migrations with the CLI before starting the updated backend. Downgrade refuses while LOINC CodeSystems remain, rather than deleting imported content. Default unversioned selection preserves the existing latest-activation order (`updated_at`, then ID); exact business versions remain selectable independently.

Parsing limits: 64 KiB manifest, 2 GiB source, two million records, 128 columns, one MiB decoded record. New raw reads per record are limited to one MiB plus at most eight KiB of prefetched input. The worker has two queued chunks; 64 KiB is a flush threshold, not a maximum chunk size, because one bounded record may expand during JSON/COPY escaping. These limits do not bound PostgreSQL staging/index/WAL memory, every HTTP request or total process RSS.

## Semantics and completeness

The official primary table is only part of `http://loinc.org`: accessory Parts and Answer String IDs require separate files. Public CodeSystem metadata therefore remains `content=not-present`, `caseSensitive=false`, with no fabricated concept enumeration. Numeric primary-code lookup and validation use complete main-table projections; absence of an LA/LP/LL or another unsupported family returns an explicit error, never a negative based on unloaded content. Supported CodeSystem reads retain selected business versions and instance identity.

Only `STATUS=DEPRECATED` maps to `inactive=true`. TRIAL and DISCOURAGED are not silently made inactive. Unknown/empty lifecycle values fail import explicitly. Blank optional columns are preserved in raw fields and omitted from projected properties; `-` is a real value. Empty `ORDER_OBS` occurs in official releases, so optional blanks are accepted. Projected display uses `LONG_COMMON_NAME`, then `SHORTNAME`, or remains absent if both are blank. Lookup uses the canonical code as its nonempty display fallback; validation does not fabricate a clinical display. All columns, including source copyright notices, are retained in `loinc_terms.fields`.

Standard `STATUS`, `CLASS`, `CLASSTYPE` and `ORDER_OBS` properties remain strings. Six CSV axis labels are exposed as custom `raw-COMPONENT`, `raw-PROPERTY`, `raw-TIME_ASPCT`, `raw-SYSTEM`, `raw-SCALE_TYP`, `raw-METHOD_TYP` strings with `urn:term-squid:loinc:column:*` URIs. They are not LP Part identifiers or inferred relationships. Every primary term also has custom `source-table=Loinc.csv` (`urn:term-squid:loinc:source-table`). CONSUMER_NAME and a raw source copyright property are retained when supplied.

The native SQL provider now supports LOINC primary terms alongside native SNOMED in include/exclude, versioned references and imported intersections, within the existing fresh repeatable-read snapshot and page/work budgets. Numeric membership in implicit `http://loinc.org/vs` is supported. That URL denotes all LOINC codes: broad expansion is rejected because accessory content is absent. Expansion must use explicit numeric concepts, a numeric code-equality filter, or an explicit `source-table=Loinc.csv` filter. Additional supported primary properties accept exact typed equality and `exists`; raw label equality is distinct from standard Part-based axis semantics. Hierarchy, LP/LA/LL sets, arbitrary ECL/regex, and mixed native/ordinary finite providers remain explicit unsupported operations.

Scope is conservatively checked on every included dependency. An imported all-code LOINC set can still make expansion fail even when an outer explicit intersection or exclusion would restrict its result. No partial count/page is returned in that case. Unversioned whole-system exclusions bind their actual canonical URL and remove that system across versions; explicit-version exclusions retain their selected release. Numeric missing codes cannot reuse stale negative results after committed projection updates.

## Typed lookup output

The shared `$lookup` adapter previously ignored projected FHIR property arrays. It now preserves property order/repetition and all seven R4 value types: code, Coding, string, integer, boolean, dateTime and decimal. It emits typed `property` groups with code/value parts on canonical and instance GET/POST routes. Coding preserves system/version/code/display/userSelected; decimal and partial dateTime are not converted to display strings. Malformed values and unsupported metadata/extensions fail explicitly. Legacy object-valued projections retain their prior wire behavior. CodeSystem POST validation also accepts the standard URI-valued `system` input.

The contract is based on the official [FHIR R4 LOINC definition](https://hl7.org/fhir/R4/loinc.html), [LOINC table structure](https://loinc.org/kb/users-guide/loinc-database-structure/loinc-table-structure), [database import examples](https://loinc.org/kb/faq/importing-loinc-into-a-database) and [LOINC staff confirmation of empty ORDER_OBS](https://forum.loinc.org/t/column-order-obs-empty/2127). Lookup response types were checked against the local official R4 4.0.1 OperationDefinition/StructureDefinition. No HTS/FHIRsmith source was copied.

All **101 Rust tests** pass: 43 backend, 16 CLI and 42 library tests, including PostgreSQL integration with no ignored scenarios. Formatting, workspace Clippy/all targets with warnings denied and all **29 harness tests / 34,217 assertions** pass. Final Cargo tests, Clippy and release builds use `--locked --offline`; the lockfile adds only `csv`/`csv-core` and preserves all previous dependency versions.

The twenty added tests cover source SHA/count/duplicate/enum/record bounds, strict quote syntax, Unicode/BOM/multiline fields, legitimate optional blanks, exact property types/lifecycle, immutable same-version conflicts, idempotence, injected publication rollback, concurrent import and cancellation. Lookup's missing-display regression checks canonical-code fallback after a committed SQL NULL update.

Identical re-import returns the same ID/fingerprint and `unchanged=true`. Nine separate production HTTP checks verify typed properties, lifecycle, absent methods, missing/accessory codes and a 50,003-member scoped expansion with an exact two-entry page.
